0.4.0 / versionCode 5 的自动更新提醒、版本测试修复、本地构建、自动化检查及正式签名已完成。维护者后续签名成功，正式四文件目录已经生成，并由助手再次独立只读预检查通过；默认、V2、V3 三轮验签均成功。维护者已明确确认本轮约定的手机基础验收通过，并授权源码提交、推送、版本标签及 GitHub 正式首发，现进入首发执行。

本报告作为首发执行前的源码归档快照，以下保留此前开发和验收事实。实际提交、草稿、公开发行及匿名下载核验结果另存于被 Git 忽略的 `build/android/github-first-release-publication/`，不提前将计划写作已完成。

此前两次签名尝试被拒绝，第二次分类为 `STORE_PASSWORD_REJECTED`；这是已经解决的历史输入问题，不能据此认定私钥丢失、证书错误或 V2/V3 失败。本轮继续使用原正式签名身份，没有重新创建密钥或改变指纹，密码和私钥未发送到聊天。

此前开发和本地准备阶段没有提交、推送、创建远程 Tag/Release 或上传 APK。applicationId、正式证书、Gradle 外签名方式、校园网认证核心和账号存储策略保持原有要求。Gitee 默认仍为 null，后续用实际优化版 0.4.1 / code 6 验证真实升级。

## 已实现的用户行为

- 新安装默认 GitHub，已保存的 AUTO/GITEE/GITHUB 选择继续保留。
- “打开 App 时检查更新”默认开启，独立存储，不与校园网自动登录开关混用。
- 每次 App 真正从后台回到前台且首页可见时检查一次；旋转、重复渲染及首页/更新页切换不重复检查。
- 自动检查与认证异步独立，不访问账号、不初始化下载器、不清理已验证 APK。
- 更高 versionCode、合法元数据且系统支持时才提醒。加载、登录、保存和账号编辑期间延后显示。
- “查看更新”进入真实更新页并重新核对发行；“稍后”关闭本次会话提醒，下次打开可以再次提醒。
- 离开前台取消请求并丢弃迟到结果；快速重新打开会等待上个任务清理，避免并发。
- 无新版、空列表、网络或安全错误不在首页弹错误窗口；更新页保留明确结果和手动重试。
- 不自动下载或安装，不后台轮询，不申请系统通知权限或使用常驻服务。

继续复用原有 GitHub 分页、HTTPS 跳转、下载进度、大小/SHA-256/包名/版本/证书校验、FileProvider、安装授权及系统安装器。本轮没有实现 Gitee 空列表/旧镜像回落或镜像同步工作流。

## 版本测试修复

Android 测试由 Gradle 当前构建参数接收期望 versionName/versionCode，替代固定的 0.3.0/4 断言。Python CLI 测试注入独立版本，避免依赖项目正式版本。

保留用于“旧版 4 → 新版 5”的合成数据；隔离实验验证了 0.4.0/5 和 0.4.1/6 的版本解析和 CLI 夹具。项目实际只改到 0.4.0/5，没有构建或发布 0.4.1。

## 0.4.0 → 0.4.1 的真实验证

保持手机安装正式 0.4.0。后续实际优化后，使用同包名、同正式签名准备 0.4.1/6；一次构建、预检查并冻结唯一 APK。

获准后发布 GitHub 稳定 `android-v0.4.1`，附齐四文件与日志，设置 `make_latest=false`。匿名核对附件 HTTPS 下载和哈希，再验证：

**手机重新进入首页 → 自动提醒 0.4.1 → 查看日志 → 确认下载 → 进度及校验 → 安装授权 → 系统覆盖安装 → 显示 0.4.1/6，配置保留。**

同时检查稍后、取消、拒绝授权及恢复；再次检查不能重复提供同版本，错误哈希/证书/版本不能进入安装。完成后才能记录为真实 GitHub 更新闭环通过。

以后只有提交代码或创建 Tag 不会产生更新，必须递增 versionCode 并发布完整 Release。此处的提醒是 App 前台检查，不是后台即时推送。
